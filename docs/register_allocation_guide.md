# 线性扫描寄存器分配算法实现指南

## 项目背景

本项目是一个编译器项目，将SysY语言编译为RISC-V汇编代码。项目采用两次遍历架构：
- 第一次遍历：收集变量的活跃区间信息
- 第二次遍历：根据寄存器分配结果生成汇编代码

当前项目结构中，`LinearScan`结构体需要实现线性扫描寄存器分配算法，用于优化变量到寄存器的分配，减少内存访问次数。

## 算法概述

线性扫描寄存器分配算法是一种高效的寄存器分配算法，时间复杂度为O(n log n)。算法的核心思想是：
1. 按照活跃区间的起始位置对所有变量进行排序
2. 从左到右扫描，为每个变量分配寄存器
3. 当寄存器不足时，选择结束时间最晚的变量溢出到栈上

## RISC-V32寄存器约定

在RISC-V32架构中，可用于通用计算的寄存器包括：

### 临时寄存器 (Temporary Registers)
- `t0-t6` (x5-x7, x28-x31)：7个临时寄存器，调用者保存
- 用于存储临时计算结果，函数调用时不需要保存

### 保存寄存器 (Saved Registers)  
- `s0-s11` (x8-x9, x18-x27)：12个保存寄存器，被调用者保存
- 用于存储需要跨函数调用保持的值

### 参数寄存器
- `a0-a7` (x10-x17)：8个参数寄存器
- 其中`a0-a1`也用作返回值寄存器

**建议分配优先级**：t0-t6 > s0-s11 > a2-a7（保留a0-a1用于返回值）

## 实现步骤

### 1. 初始化寄存器池

在`LinearScan::new()`方法中初始化可用寄存器列表：

**实现思路**：
- 创建包含所有可用寄存器名称的`Vec<String>`
- 按优先级顺序添加寄存器：先添加临时寄存器，再添加保存寄存器
- 初始化其他字段为默认值

**注意事项**：
- 保留`a0`、`a1`用于函数返回值
- 保留`sp`（栈指针）、`ra`（返回地址）等特殊寄存器
- 寄存器名称使用字符串形式，如"t0"、"s0"等

### 2. 实现活跃区间排序

**实现思路**：
- 将输入的`Vec<InnerVar>`按照`start_offset`进行升序排序
- 使用Rust的`sort_by_key`方法：`vars.sort_by_key(|v| v.get_start_offset())`

**目的**：
- 确保按照变量活跃区间的开始时间顺序处理
- 这是线性扫描算法的核心前提

### 3. 实现活跃区间管理

**数据结构设计**：
- 使用`Vec<(String, usize)>`存储当前活跃的变量，元素为(变量名, 结束时间)
- 保持该向量按结束时间升序排列

**实现思路**：
- 在处理每个新变量前，先清理已结束的活跃区间
- 清理方法：遍历活跃列表，移除结束时间小于等于当前变量开始时间的变量
- 清理时同时释放对应的寄存器回到寄存器池

### 4. 实现寄存器分配逻辑

**核心算法流程**：

```
for each 变量 in 排序后的变量列表:
    1. 清理已结束的活跃区间
    2. if 有空闲寄存器:
         分配寄存器给当前变量
         将变量加入活跃列表
         更新寄存器映射表
    3. else:
         找到结束时间最晚的活跃变量
         if 该变量结束时间 > 当前变量结束时间:
             溢出该变量到栈上
             将其寄存器分配给当前变量
             更新活跃列表和映射表
         else:
             直接将当前变量分配到栈上
```

**实现细节**：
- 寄存器分配：从`regs`向量中`pop()`一个寄存器
- 栈分配：使用`stack_offset`计算栈位置，每个变量占4字节
- 更新映射表：`reg_to_var`记录寄存器到变量的映射关系

### 5. 实现溢出处理

**溢出策略**：
- 当所有寄存器都被占用时，选择结束时间最晚的变量进行溢出
- 比较当前变量与最晚结束变量的结束时间，选择更优的分配方案

**实现思路**：
- 在活跃列表中找到结束时间最大的变量（由于列表已排序，取最后一个元素）
- 如果该变量的结束时间大于当前变量，则进行溢出交换
- 溢出时需要：
  - 将被溢出变量从寄存器映射中移除
  - 为被溢出变量分配栈空间
  - 将其寄存器分配给当前变量
  - 更新所有相关的数据结构

### 6. 实现返回值格式化

**返回值要求**：
- `HashMap<String, String>`：变量名到位置的映射
- `i32`：总的栈空间大小

**位置格式**：
- 寄存器位置：直接使用寄存器名，如"t0"、"s1"
- 栈位置：使用RISC-V内存访问格式，如"0(sp)"、"4(sp)"

**实现思路**：
- 遍历所有变量，根据分配结果构建映射表
- 栈位置格式：`format!("{}(sp)", offset)`
- 返回栈空间总大小用于函数prologue生成

### 7. 处理边界情况

**需要考虑的边界情况**：

1. **空变量列表**：直接返回空映射和0栈大小
2. **单个变量**：分配第一个可用寄存器
3. **变量数量超过寄存器数量**：正确处理溢出逻辑
4. **相同活跃区间**：按照变量名或其他稳定规则排序
5. **零长度活跃区间**：start_offset == end_offset的情况

### 8. 优化考虑

**性能优化**：
- 使用`BinaryHeap`或`BTreeSet`优化活跃区间管理
- 预先计算寄存器池大小，避免重复计算

**代码质量**：
- 添加详细的注释说明算法步骤
- 使用有意义的变量名
- 适当的错误处理和断言

**内存优化**：
- 及时清理不再需要的数据结构
- 避免不必要的字符串克隆

## 测试验证

**测试用例设计**：
1. 简单情况：变量数量少于寄存器数量
2. 溢出情况：变量数量多于寄存器数量  
3. 复杂活跃区间：重叠、嵌套、相邻的活跃区间
4. 边界情况：空列表、单变量、相同区间

**验证方法**：
- 检查分配结果的正确性：每个变量都有唯一的位置
- 验证寄存器冲突：同一时间点不能有两个变量使用同一寄存器
- 检查栈空间计算：确保栈大小足够容纳所有溢出变量

## 与项目集成

**集成点**：
- 在`build_function`函数的第324-328行调用寄存器分配器
- 分配结果通过`GenContext::record_alloca_vars`记录
- 第二次遍历时通过`GenContext::get_location`获取变量位置

**输出格式**：
- 寄存器分配结果用于生成RISC-V汇编指令
- 栈空间大小用于生成函数prologue和epilogue
- 位置信息用于load/store指令的地址计算

## 总结

线性扫描寄存器分配算法通过简单高效的线性扫描过程，在保证正确性的前提下实现了较好的寄存器利用率。该算法特别适合编译器的快速编译场景，在代码质量和编译速度之间取得了良好的平衡。

实现时需要特别注意RISC-V架构的寄存器约定，正确处理溢出情况，并确保与现有代码生成框架的良好集成。
